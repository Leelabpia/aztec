# 자산관리 웹앱 — 사업장 자산 등록부

사업장(업장) · 건물 · 층 단위로 자산을 등록하고, **실제 도면 위에 자산 위치를 배치**해 관리하는 정적(static) 웹 애플리케이션입니다.
서버가 필요 없고, **Google Drive에 데이터를 저장**하며, **GitHub Pages에 그대로 배포**할 수 있습니다.

- 한 개의 파일(`index.html`)로 동작 — HTML · CSS · JavaScript가 모두 인라인
- 데이터는 ① 브라우저 저장소(로컬) + ② Google Drive(`자산관리/asset-manager-data.json`) 두 곳에 저장
- 사진은 **파일 선택** 또는 **휴대폰 카메라 촬영**으로 바로 등록

---

## 1. 요구사항 대응표

| 요구사항 | 구현 |
|---|---|
| ① 메인화면 = 대시보드, 업장별 · 층별 · 재고자산의 수량 및 금액 | `대시보드` — KPI 4종(수량·취득원가·감가누계·장부가액), 사업장별 장부가액 차트, 자산 종류별 도넛, **층별 자산 현황 표(사업장 소계 포함)**, 사업장 요약 카드, 최근 등록 자산 |
| ② 메인화면에서 실제 도면 배치 + 자산 위치 표시 | `도면 배치` — 층별 도면 이미지를 올리고, 자산을 **핀 마커**로 배치. 드래그로 이동, 좌표(%)로 저장, 확대/축소, 인쇄 |
| ③ 관리자 모드에서 사업장 · 층 · 자산 등록/수정/삭제 | `관리자 모드` — 사업장 / 건물 / 층 / 자산 / 자산종류 CRUD (PIN 잠금) |
| ④ 신규 자산 등록 항목 8종 | 제품사진 · 제품명 · 제품가격 · 구입업체 · 구입금액 · 감가금액 · 자산의 종류 · 기타 (+ 수량·구입일·상태·관리번호·위치) |
| ⑤ Google Drive 연동(내 드라이브에 저장) | `데이터 · 백업` / `설정` — Google Identity Services + Drive API v3, `drive.file` 범위. 폴더 자동 생성, 데이터 JSON 저장, 사진 원본 업로드 |
| ⑥ GitHub 배포용 파일 | 이 저장소 구조 그대로 `git push` → GitHub Pages 활성화 (README 5장) |

## 2. 빠른 시작 (설치 없이 바로 보기)

```bash
# 1) 저장소 내려받기
git clone https://github.com/<계정>/<저장소>.git
cd <저장소>

# 2) 로컬 서버로 열기 (권장 — 파일을 직접 열면 일부 기능이 제한됩니다)
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

처음 열면 등록부가 비어 있습니다. 대시보드의 **`샘플 데이터 불러오기`** 를 누르면
사업장 2곳 · 건물 4동 · 층 6개 · 자산 11건 · **도면 6장**이 예시로 채워져 전체 기능을 바로 확인할 수 있습니다.

> `index.html`을 더블클릭(`file://`)해도 조회·등록·백업은 모두 동작합니다.
> 다만 **Google Drive 로그인은 https/http 주소에서만** 허용되므로 `file://`에서는 로컬 저장 모드로 사용하세요.

## 3. 화면 안내

### 대시보드 (`#/dashboard`)
- **KPI** — 총 재고 수량(점), 취득원가 합계, 감가상각누계, 장부가액 합계
- **사업장별 장부가액** 막대 / **자산 종류별 장부가액** 도넛
- **층별 자산 현황** — 사업장 소계 → 건물/층 단위로 자산수 · 수량 · 취득원가 · 감가누계 · 장부가액. 층 이름을 클릭하면 해당 층 도면으로 이동
- **사업장 요약 카드** — 건물/층/자산 수, 취득·감가·장부 비율, 도면 등록률

### 도면 배치 (`#/floorplan`)
- 왼쪽 트리에서 **사업장 → 건물 → 층** 선택
- 가운데: 도면 시트(청사진 그리드) + 자산 마커. 상단에서 확대(`+/−`), `맞춤`, `인쇄`
- 오른쪽: **자산 상세**(제품사진·금액·좌표·기타) + **층 자산 목록**
- 관리자 모드에서는 **마커를 드래그해 위치를 이동**하고, `위치 지정` → 도면 클릭으로 좌표를 새로 지정합니다. 좌표는 0~100% 비율로 저장되어 창 크기나 접속 기기에 관계없이 같은 위치에 표시됩니다.

### 자산 목록 (`#/assets`)
- 검색(제품명·구입업체·기타·관리번호), 사업장/종류/상태/층 필터
- 열 제목 클릭 정렬(제품명·종류·위치·구입업체·수량·구입금액·감가금액·장부가액)
- 하단 합계 행, `CSV 내보내기`(Excel에서 바로 열리는 UTF-8 BOM), 관리자 모드에서 **선택 삭제**

### 관리자 모드 (`#/admin`)
기본 PIN은 **`0000`** (데이터·백업 또는 설정 탭에서 변경). 탭 구성:

| 탭 | 기능 |
|---|---|
| 사업장 · 층 | 사업장 등록/수정/삭제 → 건물 등록 → 층 등록, **층별 도면 업로드/교체**, 배치 화면 이동 |
| 자산 | 신규 자산 등록, 수정, 삭제(개별·선택 일괄), CSV |
| 자산 종류 | 종류 등록/수정/삭제(식별 색상 — 마커·범례에 반영) |
| 설정 | Google Drive 연결 설정, 회사명(표제란), 자동 저장 여부, 사진 원본 업로드 여부, PIN 변경 |

> PIN은 브라우저에만 저장되는 **간단한 잠금**입니다. 실제 보안 장치(서버 인증)가 아닙니다.

### 데이터 · 백업 (`#/data`)
- 드라이브 연결 / 지금 저장 / 불러오기, 데이터 크기·사진 수, 도면 등록 현황
- **백업 파일(JSON) 내려받기·불러오기** — 사진 썸네일 포함이라 PC를 옮겨도 그대로 복원됩니다
- 자산목록 CSV, 전체 초기화, 샘플 데이터

---

### 모바일 (스마트폰 · 태블릿 ≤ 860px)
- 좌측 메뉴는 **슬라이드 서랍**으로 접힙니다 — 헤더 왼쪽 `☰` 버튼으로 열고, 항목 선택·바깥 터치·`Esc` 로 닫힙니다.
- 상단 표제란(도면 표제란 스트립)은 **2열로 접혀** 넘침 없이 표시되고, 자산 표는 열 폭을 유지한 채 **가로 스크롤**됩니다.
- 자산 등록 등 모달은 화면 하단에서 올라오는 **시트 형태**로 표시됩니다(내부 스크롤 · 하단 고정 버튼).
- 도면 마커는 손가락으로 **탭해 선택**, 관리자 모드에서는 **드래그해 이동**할 수 있습니다. 좌표는 비율로 저장되어 기기와 무관하게 동일한 위치에 표시됩니다.
- 사진 등록은 `카메라 촬영` 버튼으로 휴대폰 카메라를 바로 열 수 있습니다.

## 4. 자산 등록 항목

| 항목 | 필수 | 설명 |
|---|---|---|
| 제품 사진 |  | 이미지 파일 선택 또는 **카메라 촬영**. 표시용 썸네일(최대 960px)이 앱에 저장되고, 드라이브 연결 시 **원본이 `photos` 폴더에 업로드**됩니다 |
| 제품명 | ✔ | 예) 노트북 16인치 |
| 제품가격 |  | 단가(원). 구입금액을 비우면 `제품가격 × 수량`이 취득원가가 됩니다 |
| 구입업체 |  | 예) OO전자 |
| 구입금액 |  | 취득원가(총액). 감가·장부가액 계산의 기준 |
| 감가금액 |  | 감가상각누계액 |
| 자산의 종류 | ✔ | 자산종류 목록에서 선택(비품 / IT장비 / 기계설비 / 차량·운반 / 기타 — 자유롭게 추가 가능) |
| 기타 |  | 규격·시리얼·비고 등 자유 기재(여러 줄 가능) |
| 수량 / 구입일 / 상태 / 관리번호 / 위치(층) | 위치만 ✔ | 수량 기본값 1, 상태(사용중·보관·수리·처분·폐기) |

### 금액 계산 규칙
```
취득원가   =  구입금액            (미입력 시 → 제품가격 × 수량)
감가상각누계 =  감가금액
장부가액   =  취득원가 − 감가금액
```
등록부 전체 집계(대시보드 KPI · 층별 현황 · 사업장 소계)는 위 정의로 합산합니다.
수량은 **점(point)** 단위 합계이며, 금액은 자산 1건(=수량 묶음) 기준의 구입금액입니다.

## 5. Google Drive 연동 설정

정적 웹앱이므로 **서버 없이** 브라우저에서 직접 Google Drive API를 호출합니다(OAuth 2.0 토큰 모델).
필요한 것은 **OAuth 클라이언트 ID 하나**입니다. (클라이언트 보안 비밀값은 사용하지 않습니다.)

### 5-1. Google Cloud Console 준비
1. <https://console.cloud.google.com/> 접속 → 상단에서 **프로젝트 만들기** (예: `asset-manager`)
2. **API 및 서비스 → 라이브러리** → `Google Drive API` 검색 → **사용 설정**
3. **API 및 서비스 → OAuth 동의 화면**
   - User Type: 조직 계정이면 `내부`, 개인 Gmail이면 `외부`
   - 앱 이름·지원 이메일·개발자 이메일 입력 후 저장
   - `외부`인 경우 **테스트 사용자**에 본인 Gmail 계정을 추가해야 로그인이 됩니다
   - 범위(Scope)는 앱에서 요청하는 `.../auth/drive.file` 만 있으면 충분합니다
4. **API 및 서비스 → 사용자 인증 정보 → 사용자 인증 정보 만들기 → OAuth 클라이언트 ID**
   - 애플리케이션 유형: **웹 애플리케이션**
   - **승인된 JavaScript 원본**에 접속 주소를 추가합니다 (여러 개 가능)
     - GitHub Pages: `https://<계정>.github.io`
     - 로컬 테스트: `http://localhost:8000`
   - 만들기 → 표시되는 `...apps.googleusercontent.com` 값을 복사

### 5-2. 앱에 클라이언트 ID 넣기 (둘 중 하나)
- **방법 A (권장, 배포용)** — `index.html` 상단의 상수를 수정합니다.
  ```js
  const DEFAULT_CLIENT_ID = "1234567890-abcdefg.apps.googleusercontent.com";
  ```
  이후 앱을 처음 여는 사용자에게 자동 적용됩니다.
- **방법 B (앱 안에서)** — `관리자 모드 → 설정`(또는 `데이터 · 백업 → 설정 열기`)에서
  `OAuth 2.0 클라이언트 ID`에 붙여넣고 **설정 저장** → **드라이브 연결**

### 5-3. 연결 후 동작
- 드라이브에 `자산관리` 폴더를 만들고 `asset-manager-data.json` **한 파일**에 전체 데이터를 저장합니다(없으면 자동 생성)
- 사진 원본은 같은 폴더의 `photos/` 하위 폴더에 업로드됩니다
- 요청 범위는 `drive.file` — **이 앱이 만든 파일만** 읽고 쓸 수 있습니다. 기존 드라이브 문서는 접근하지 않습니다
- 접근 토큰은 브라우저 메모리에만 있으며 약 1시간 후 자동으로 갱신을 시도합니다
- 연결 후에는 변경이 생기면 6초 뒤 자동 저장됩니다(설정에서 끌 수 있음). `Ctrl/Cmd + S` 로 즉시 저장할 수도 있습니다

### 5-4. 여러 대에서 쓸 때
드라이브 연결 시 원격 사본이 더 최신이면 “드라이브에 더 최신 데이터가 있습니다” 안내가 뜨고, 가져오기를 선택할 수 있습니다.
같은 파일을 여러 사람이 동시에 편집하는 구조는 아니므로, **동시 편집은 피하고** 필요 시 `백업 파일 내려받기`로 사본을 교환하세요.

## 6. GitHub Pages 배포

```bash
# 1) 저장소 만들기 (GitHub 웹에서 New repository, 이름 예: asset-manager)
# 2) 이 폴더에서 실행
git init
git add -A
git commit -m "feat: 자산관리 웹앱 초기 배포"
git branch -M main
git remote add origin https://github.com/<계정>/<저장소>.git
git push -u origin main
```

3) GitHub 저장소 → **Settings → Pages**
   - Source: `Deploy from a branch`
   - Branch: `main` / 폴더: `/ (root)` → **Save**
4) 1~2분 뒤 `https://<계정>.github.io/<저장소>/` 로 접속됩니다.
5) Google Drive 로그인이 되게 하려면 5-1-(4)의 **승인된 JavaScript 원본**에 위 주소(`https://<계정>.github.io`)를 반드시 추가하세요.

> `.nojekyll` 파일이 포함되어 있어 Jekyll 처리 없이 그대로 정적 파일로 서빙됩니다.

### 폴더 구조
```
.
├── index.html      # 앱 전체 (HTML + CSS + JS 인라인)
├── README.md       # 이 문서
├── LICENSE         # MIT
├── .nojekyll       # GitHub Pages용
└── .gitignore
```

## 8. 저장 · 용량 정책

| | 저장 위치 | 비고 |
|---|---|---|
| 데이터 JSON | 브라우저 localStorage **+** Google Drive | 항상 로컬 사본이 있어 오프라인 조회 가능 |
| 자산 사진 | 앱에는 썸네일(최대 960px, JPEG) / Drive에는 원본 | 로컬 용량을 아끼기 위해 썸네일만 보관 |
| 도면 이미지 | 앱에 최적화본(최대 1600px, JPEG) | 드라이브 연결 시 원본도 함께 업로드 |

브라우저 localStorage는 보통 **5MB** 한도입니다. 사진·도면이 많아지면 한도에 가까워지므로
`데이터 · 백업` 화면의 **데이터 크기**를 확인하고, 커지면 ① 드라이브에 저장하고 ② `백업 파일 내려받기`를 받아 두고 ③ 필요 없는 자산의 사진을 정리하세요.
저장 공간이 가득 차면 앱이 “로컬 저장 실패” 토스트로 알려줍니다(이때도 드라이브 저장은 계속 동작합니다).

## 9. 문제 해결

| 증상 | 원인 / 해결 |
|---|---|
| `드라이브 연결` 시 `Google 인증 오류: popup_closed` / `idpiframe` | 팝업 차단 해제, 또는 승인된 JavaScript 원본에 현재 주소가 등록되지 않음(5-1-(4)) |
| `Google Drive 연결은 https 주소에서만 동작합니다` | `file://` 로 열었습니다. `python3 -m http.server 8000` 으로 열거나 GitHub Pages 주소를 사용하세요 |
| 로그인 화면에서 `액세스 차단됨: 이 앱의 요청이 유효하지 않습니다` | OAuth 동의 화면이 `외부`이고 본인 계정이 **테스트 사용자**에 없음 |
| `Drive API 오류 403 — insufficientPermissions` | 다른 Google 계정으로 로그인됨, 또는 5-1-(2) Drive API 사용 설정 누락 |
| 도면은 보이는데 마커가 안 보임 | 관리자 모드에서 해당 자산의 `위치 지정`을 실행하거나 마커를 드래그하세요 |
| 사진이 등록되지 않음 | HEIC 원본은 브라우저가 해석하지 못할 수 있습니다. 카메라 촬영 또는 JPG/PNG로 변환 후 등록하세요 |
| 데이터가 사라진 것처럼 보임 | 브라우저 저장소를 지웠거나 다른 브라우저입니다. `데이터 · 백업 → 드라이브에서 불러오기` 또는 백업 JSON을 사용하세요 |

## 10. 단축키 · 기타
